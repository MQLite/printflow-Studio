# Local AI design result receiver

This Node 24 service accepts one PNG or JPEG through an official MCP `save_image_result` file parameter. It stores an immutable receipt and blob for a previously enrolled request/attempt. A foreground monitor can independently download the exact version and write a verified candidate into a separate inbox. Trial Studio can also resume one existing Work result and import the original as a Prepare Design Asset session.

## Local setup

Run `npm ci` in this directory. Copy `config.example.json` to an absolute `receiver.local.json` path, choose a private absolute `storageRoot`, generate three distinct high-entropy bearer secrets, and set an exact approved HTTPS file origin and path prefix. Keep config, tickets, storage, and inbox out of Git. The module ignores `*.local.json` and `data/` inside this directory. Protect external paths with normal OS file permissions.

Start the service with `node src/cli.mjs serve --config ABSOLUTE_CONFIG_PATH`. It listens only on `127.0.0.1`, default port `32179`, with MCP at `/mcp`. Unchanged example bearer values are refused. The service keeps one writer lock per storage root. A second process fails; after a crash, a lock is reclaimed only if the recorded PID is proven exited. An uncertain owner requires manual inspection.

For direct legacy enrollment, an independently trusted controller can pre-bind the exact newly generated source `file_id` to the request and attempt. Use `node src/cli.mjs enroll --config ABSOLUTE_CONFIG_PATH --request REQUEST_ID --attempt ATTEMPT_ID --expected-file-id VERIFIED_FILE_ID --out ABSOLUTE_TICKETS.local.json`. The source ID is treated as an opaque bounded string, including URI-shaped IDs; it is hashed for storage paths and never used as a filename. The ticket file is created without overwrite and contains the attempt-scoped upload and read tickets. Give only `uploadTicket`, request ID and attempt ID to the Work caller. Never give Work the control/read bearer or the read ticket. If independent binding is unavailable at enrollment, omit `--expected-file-id`. The monitor publishes only after independently verified source binding.

Run `node src/cli.mjs monitor --config ABSOLUTE_CONFIG_PATH --ticket ABSOLUTE_TICKETS.local.json --inbox ABSOLUTE_INBOX_PATH` while the application is active. It polls for at most two minutes and exits; direct `monitorOnce` calls also have a two-minute default deadline. A verified candidate is one complete inbox directory containing original image bytes and a receipt; incomplete staging directories are ignored. Repeated and concurrent reads verify the same object without overwriting unrelated files. `node src/cli.mjs cancel --config ABSOLUTE_CONFIG_PATH --request REQUEST_ID --attempt ATTEMPT_ID` revokes the current attempt, including one already received. Enrolling a newer attempt for the same request fences the older attempt. Neither command resubmits image generation.

The control API is `POST /control/attempts` and `POST /control/attempts/:requestId/:attemptId/cancel` with the control bearer. The read API is `GET /results/:requestId/:attemptId` and `GET /results/:requestId/:attemptId/blob/:objectVersion` with the distinct read bearer and `x-read-ticket`. The MCP writer bearer reaches only `/mcp`. Source URLs must match the approved HTTPS origin and path prefix. DNS answers are checked for public IPv4/IPv6 addresses and the selected address is pinned for the TLS connection; private/loopback/reserved answers and redirects are rejected. The source request uses identity content encoding, rejects encoded responses and mismatched declared lengths, and has a two-minute total deadline. Files are capped at 40 MiB and fully decoded with a 64 million pixel cap; decoding is serialized and streamed to a bounded discard sink while the original bytes are retained.

## Binding a Studio return

Use the [trial setup](../../docs/codex/printflow-ai-design-backlog/WORK_RESULT_TRIAL.md) to have Studio enroll each attempt over a private Windows named pipe. Studio and the receiver run as the same user. The pipe is used only for enrollment, cancellation, receipt queries and exact-version bytes. Network access stays in the independent receiver. After Chrome confirms submission, Studio sends its conversation ID and private read ticket over the pipe. Studio-enrolled returns are accepted after checking the stored bytes and excluding copies of reference attachments. Studio checks the returned file before importing it. A second upload or independent source lookup is unnecessary.

The legacy independent-source workflow holds the result at `received_unverified` until a controller verifies the exact original from the **same Work conversation**, apart from the MCP upload. Save the following values as a private `source-evidence.local.json` (the values are fields, not evidence on their own):

- `requestId`, `attemptId`, and `workConversationId` matching the confirmed Studio request.
- `expectedFileId` from the independently observed original, `expectedSha256` in lowercase, and `expectedByteLength` as a number. Obtain the digest and length by reading the original bytes, never by copying the upload receipt or accepting a model claim.
- `allowReissuedFileId` may be set to true if the platform assigns a fresh file ID. In that case the independently observed digest and byte length still have to match exactly.

Run `node src/cli.mjs bind-source --config ABSOLUTE_RECEIVER.local.json --evidence ABSOLUTE_EVIDENCE.local.json`. Binding can happen before or after the upload. A mismatch leaves the upload unverified. If the wrong file was returned, use the original in the manual import route; Studio does not replace the quarantined object with a second upload. If the monitor already timed out, restart trial Studio with the same configuration to check for the now verified result. No supported automatic source observation has been confirmed for a fresh Work result.

To resume a legacy manually enrolled result, run trial Studio with `--resume-work-result ABSOLUTE_CONFIGURATION.local.json`. The private JSON configuration contains `requestId`, `attemptId`, `workConversationId`, `pipeName` (the receiver's `studioPipe`), `sourceFileId`, `sourceSha256`, `readBearer`, `readTicket` and `outputName`. Set `allowReissuedFileId` only if the receiver was bound to the original digest for that attempt. Studio reads the authenticated receipt, verifies the image again, and imports it once. This entry resumes a confirmed Work submission.

The monitor rechecks the same authenticated Ready receipt immediately before publishing its local candidate. A cancellation completed before that final observation prevents publication. Cancellation after that observation requires a later PrintFlow T08 check of the current local attempt and state version before any Session import; this standalone probe never imports a Session. A crash after server enrollment but before the local ticket file is flushed leaves an unusable pending attempt; cancel the known request/attempt and enroll a fresh tracking attempt without resubmitting generation.

`npm test` uses synthetic local images and an injected source fetcher. It proves local SDK calls, storage and monitoring only. A separate 2026-10-05 probe uploaded a known synthetic PNG through the user-connected Google Drive plugin, obtained its authenticated raw file reference, then used the production HTTPS fetcher, official local MCP client and monitor. The original bytes, dimensions and SHA-256 matched. The probe's trusted source enrollment applies only to that known synthetic file; it does not prove Work-generated provenance, a Drive upstream version or an unattended Drive OAuth/changes adapter.
