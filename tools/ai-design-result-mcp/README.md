# Local AI design result receiver

This standalone Node 24 service accepts one PNG or JPEG through an official MCP `save_image_result` file parameter. It stores an immutable receipt and blob for a previously enrolled request/attempt. A foreground monitor independently downloads the exact version and writes a verified candidate into a separate inbox. It does not connect to PrintFlow's Session importer.

## Local setup

Run `npm ci` in this directory. Copy `config.example.json` to an absolute `receiver.local.json` path, choose a private absolute `storageRoot`, generate three distinct high-entropy bearer secrets, and set an exact approved HTTPS file origin and path prefix. Keep config, tickets, storage, and inbox out of Git. The module ignores `*.local.json` and `data/` inside this directory. Protect external paths with normal OS file permissions.

Start the service with `node src/cli.mjs serve --config ABSOLUTE_CONFIG_PATH`. It listens only on `127.0.0.1`, default port `32179`, with MCP at `/mcp`. Unchanged example bearer values are refused. The service keeps one writer lock per storage root. A second process fails; after a crash, a lock is reclaimed only if the recorded PID is proven exited. An uncertain owner requires manual inspection.

Before any upload, an independently trusted controller must bind the exact newly generated source `file_id` to the request and attempt. Use `node src/cli.mjs enroll --config ABSOLUTE_CONFIG_PATH --request REQUEST_ID --attempt ATTEMPT_ID --expected-file-id VERIFIED_FILE_ID --out ABSOLUTE_TICKETS.local.json`. The file is created without overwrite and contains the attempt-scoped upload and read tickets. Give only `uploadTicket`, request ID and attempt ID to the Work caller. Never give Work the control/read bearer or the read ticket. If independent `file_id` binding is unavailable, omit `--expected-file-id` only for diagnostic storage: the result remains `received_unverified` and the monitor will not publish it.

Run `node src/cli.mjs monitor --config ABSOLUTE_CONFIG_PATH --ticket ABSOLUTE_TICKETS.local.json --inbox ABSOLUTE_INBOX_PATH` while the application is active. It polls for at most two minutes and exits; direct `monitorOnce` calls also have a two-minute default deadline. A verified candidate is one complete inbox directory containing original image bytes and a receipt; incomplete staging directories are ignored. Repeated and concurrent reads verify the same object without overwriting unrelated files. `node src/cli.mjs cancel --config ABSOLUTE_CONFIG_PATH --request REQUEST_ID --attempt ATTEMPT_ID` revokes the current attempt, including one already received. Enrolling a newer attempt for the same request fences the older attempt. Neither command resubmits image generation.

The control API is `POST /control/attempts` and `POST /control/attempts/:requestId/:attemptId/cancel` with the control bearer. The read API is `GET /results/:requestId/:attemptId` and `GET /results/:requestId/:attemptId/blob/:objectVersion` with the distinct read bearer and `x-read-ticket`. The MCP writer bearer reaches only `/mcp`. Source URLs must match the approved HTTPS origin and path prefix. DNS answers are checked for public IPv4/IPv6 addresses and the selected address is pinned for the TLS connection; private/loopback/reserved answers and redirects are rejected. The source request uses identity content encoding, rejects encoded responses and mismatched declared lengths, and has a two-minute total deadline. Files are capped at 40 MiB and fully decoded with a 64 million pixel cap; decoding is serialized and streamed to a bounded discard sink while the original bytes are retained.

The monitor rechecks the same authenticated Ready receipt immediately before publishing its local candidate. A cancellation completed before that final observation prevents publication. Cancellation after that observation requires a later PrintFlow T08 check of the current local attempt and state version before any Session import; this standalone probe never imports a Session. A crash after server enrollment but before the local ticket file is flushed leaves an unusable pending attempt; cancel the known request/attempt and enroll a fresh tracking attempt without resubmitting generation.

`npm test` uses synthetic local images and an injected source fetcher. It proves local SDK calls, storage and monitoring only. A localhost address is not reachable by ChatGPT Work by itself. A real Work connection needs a supported authentication path and reachable endpoint, such as an authorized Secure MCP Tunnel with its separate Platform permissions and runtime credentials. ChatGPT cannot present an arbitrary static API key for this local bearer scheme. No tunnel, OAuth mapping, account connection, remote upload, or real Work source binding has been performed. The source `file_id` shown in file parameters has not yet been independently tied to the actual generated image in Work; a filename or viewer path does not establish that relationship.
