## 0. 当前有效的结果交接修订 — 2026-10-05

用户最新要求：最终流程不要使用浏览器控制工具下载结果，尝试将生成结果上传到某个 MCP Server 或 Google Drive 的特定目录，由程序监控并读取。这项指示立即生效。下方第 1–12 节保留原已批准、部分已实现的本地下载方案及验收来源；其中输出采用浏览器下载、唯一 `downloadId`、仅允许本地输出交接、排除 MCP／Drive 输出连接的规定，现由本节替代。输入附件上传、Chrome／真实 Work、一次提交、停止、图片校验和幂等导入继续有效。

当前流程：

`需求＋附件 → Prompt → 必要附件上传确认 → Chrome Work 生图 → 上传指定存储 → 程序监控完成回执 → 读取并校验图片 → 幂等素材导入`

### 接入选择与已知能力

- **已有 MCP 接收服务**：建议的可控交接边界。Work 调用接收工具，使用官方 `_meta["openai/fileParams"]` 文件对象交接真实结果；服务器取得完整文件并发布后返回稳定对象 ID、版本、长度和 SHA-256。程序只查询本请求／尝试的完成记录。服务地址、工具清单、认证及存储目录尚未提供。官方文件参数支持不证明当前账号能把这两张生成图片交给该工具。
- **Google Drive 上传工具＋特定目录**：先验证连接后的工具支持把 Work 生成 PNG/JPEG 作为真实二进制文件创建在准确 folder ID 中，返回 file ID。程序使用独立的经授权读取连接监控该目录，按固定 file ID／版本读取。官方 API 支持上传与 changes 游标；ChatGPT 的 Drive 连接不自动赋予桌面程序 OAuth 凭据。若已有 Drive 桌面同步配置，可评估限定目录的同步接收，仍需完成回执与内容校验。

首轮只接入用户确定且实际可用的一种提供方。此前 Google Drive 仅可发现；连接器可见也不证明它支持二进制上传。本轮 Work 生成结果菜单仅观察到 Space、文件信息、收藏、反馈，以及 viewer 的分享控件，未证实外部上传；composer 没有可见的 Drive 或指定 MCP 接收插件。用户随后提出“如果没有这类 MCP 的话，能否考虑自己做一个 MCP 服务？”，本轮据此先完成下述独立本地接收器／监控探针。已有服务器或 Drive 目录仍是可选后续接入，不再阻塞本地模块准备；目标连接、认证和真实上传不会由本地测试自动获得。

### 监控、接收与导入合同

程序在生图前保存指定提供方、目标范围、requestId、attemptId 和本次交接身份。远端完成回执绑定本次生成结果、稳定对象 ID、版本／完成身份、长度和 SHA-256；文件名仅辅助诊断，不能代替对象身份，Drive file ID 也不等于版本。Work 只交接本次新生成的单张原始结果，不能采用参考图、缩略图、历史结果或其他请求的文件。存储凭据和临时文件 URL 不进入 Prompt 日志、报告或 Git。

监控仅在应用运行期间执行，按提供方完成记录或经过分页、持久游标处理的指定目录变化读取。重复通知、程序重启和重放仍只导入一次；不扫描账户所有文件，不按“最新图片”猜测结果，不增加常驻系统服务或计划任务。只在远端完整发布后，按固定对象／版本读取到本请求暂存位置，独立计算长度、SHA-256 和实际格式，仍限 PNG/JPEG、40 MiB、64 百万像素，再原子发布候选并进入原幂等导入事务。半文件、错尝试、版本变化、停止后迟到文件均不能自动导入。

停止使本地交接身份失效并禁止采用迟到结果，不宣称远端文件已删除。重启不再次提交生图；已知完整对象可核验后继续接收。上传或读取失败保留 Prompt、必要附件与手动图片导入。网络读取边界在提供方确定后明确到模块；保留生产、诊断、安装和包策略，不删除测试或全局放宽网络限制。已有下载 DTO／状态事件属于旧实现基线，T08 必须修订，不能填造 downloadId 来兼容远端对象。

### 验收与授权边界

T02 验证真实 Work 文件上传到所选存储的能力；T07 保留真实输入附件与单次提交验收；T08 改为对象绑定、监控读取及严格图片接收；T11 分别证明两条链路的 request → attempt → generation result → remote object/version → independently verified bytes/hash → unique Session。原任务依赖保持，历史 PASS 不证明新接口已实现。

收到目标和有效连接后，优先上传已有两条 Chrome Work 试验的结果，不重新生图，不调用浏览器控制工具下载。真实远端对象与独立读取证据才能满足验收；链接分享、本地合成文件、假上传或夹具 PASS 不等于 Work 结果上传。当前上传与监控读取均 NOT RUN，自动通道继续禁用。

用户授权了结果上传／读取方向及独立本地 MCP 增量；外部目标、账户与访问范围仍需明确。不得擅自创建公网服务、部署 Linux、购买服务、更改生产安装、上传客户作品或推送／发布代码。新增部署、隧道和真实账号连接须单独明确；当前可完成本地实现与测试，真实 Work 交接仍缺少已授权且可达的连接和来源身份绑定。

官方来源：[OpenAI MCP 文件参数](https://developers.openai.com/plugins/reference#file-apis)、[Work 连接 MCP 插件](https://developers.openai.com/plugins/quickstart)、[Drive 上传](https://developers.google.com/workspace/drive/api/guides/manage-uploads)、[Drive 变化游标](https://developers.google.com/workspace/drive/api/guides/manage-changes)。它们证明接口存在，未证明本账号、目标目录或生成图片交接已可用。

### 自建 MCP：本轮最小可运行边界

新增独立 `tools/ai-design-result-mcp/` Node ESM 模块，不加入产品 solution、MSI 或开机项。父执行上下文已核验 Node 24.14.0 及官方模块 `@modelcontextprotocol/server`／`client` 2.3.0、`@modelcontextprotocol/node` 2.1.1 和 zod 4 可用，并核验 sharp 0.35.5 可作受限完整图片解码器；本增量允许自己的 `package.json`／锁文件，不扩大旧产品包规则。采用已核验 SDK 的 Streamable HTTP handler，默认仅绑定明确的 loopback 地址与固定 `/mcp`，私有存储根使用持久单写者所有权锁。第二进程不得并发打开同一根；崩溃后的锁回收必须先证明原拥有者已退出，不能按锁龄删除活锁，无法确认时失败关闭。限制 Host／Origin、请求体长度、并发和超时；不用手写的简化 JSON-RPC 冒充完整 MCP。工具不需要网页组件、额外生图 API 或常驻监控服务。

本地服务可由 CLI／SDK 客户端真实调用；这不代表 ChatGPT 网页能访问 localhost。当前官方指南支持可达 HTTPS MCP 端点，或将私有 stdio／HTTP 服务接入 Secure MCP Tunnel。后者需要 `tunnel_id`、运行凭据与独立 Platform 权限，不能由已有 Plus／Pro 推定，不能在本轮自动创建／安装／启用。公开部署与隧道均保持未执行。依据：[连接前提](https://developers.openai.com/plugins/deploy/connect-chatgpt)、[私有 MCP 隧道及权限](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)。

模块内建议落点与边界如下；仅此表是实现建议，不表示文件已经存在：

### 工具文件参数与消息合同

MCP 只对 Work 暴露 `save_image_result`，用途是接收一份当前尝试生成的原始图片。顶层参数为 `request_id`、`attempt_id`、`upload_ticket`、`file`，均必填；禁止额外参数、目标路径、任意存储桶、任意读取 URL 等通用能力。请求／尝试 ID 是关联值，`upload_ticket` 则是由控制面签发、限定该尝试且可撤销的上传能力，不能读取结果、取消请求或提升来源信任。`_meta["openai/fileParams"] = ["file"]`；文件对象必须严格使用以下形状：

```json
{
  "type": "object",
  "properties": {
    "download_url": { "type": "string" },
    "file_id": { "type": "string" },
    "mime_type": { "type": "string" },
    "file_name": { "type": "string" }
  },
  "required": ["download_url", "file_id"],
  "additionalProperties": false
}
```

四个属性必须都声明，只能要求其中 `download_url` 和 `file_id` 必填；文件名／MIME 不能作为可信格式或路径。该官方约定是平台把文件引用和临时取件 URL 交给工具，再由接收服务有界读取文件，**不涉及浏览器控制下载**。文档没有保证当前 Work 的 imagegen 输出一定可转换为该参数，也没有提供由 `file_id` 本身证明生成来源的通用机制。[文件参数规范](https://developers.openai.com/plugins/reference#file-apis)

工具标注 `readOnlyHint=false`、`destructiveHint=false`、`idempotentHint=true`，且 `openWorldHint=true` 明示它会读取外部 HTTPS 文件；这些标注不能替代服务端授权。输出须有 `outputSchema`，返回结构化 `SaveImageResultReceipt`，不返回密钥、临时 URL 或本地绝对路径。[工具描述与结果原则](https://developers.openai.com/plugins/build/mcp-server)

| DTO／操作 | 关键字段与裁决 |
| --- | --- |
| 本地 `EnrollResultRequest` | `requestId, attemptId, expectedFileId?`；控制身份由认证上下文取得，不能由参数冒充。生成分别限定上传／读取的随机 ticket，持久化其 hash、登记版本与撤销状态；可登记未绑定源的尝试，但不能由此进入自动接收。已登记身份的来源不可由重复调用静默改写。 |
| `SaveImageResultInput` | `request_id, attempt_id, upload_ticket, file`；服务器把 MCP writer、有效上传 ticket、登记尝试和 source `file_id` 一并核验。 |
| `SaveImageResultReceipt` | `schemaVersion, requestId, attemptId, status, objectId, objectVersion, sourceFileId, byteLength, sha256, mediaType, width, height, sourceVerified`；可用时附 `completedAt`。`status` 明确为 `received_unverified` 或 `Ready`；后者表示完整且源已核验的不可变发布，前者没有可导入的完成身份。 |
| 本地 `CancelResultRequest` | 准确 request/attempt；在锁内更新登记版本并使 ticket 失效，与最终发布串行裁决。 |
| 本地 `GetResultReceipt`／`ReadPublishedObject` | 每次验证该尝试的 read ticket，并只按准确尝试及对象版本读取；返回 Pending、received_unverified、Ready、Cancelled 或结构化错误。不提供枚举全部文件、最新文件、任意路径或任意 URL 读取。 |

本地 control/read bearer 与 MCP writer bearer 分开，并增加每尝试不同的 upload/read ticket；MCP 调用者不能登记目标来源、撤销其他请求或读取任意结果。只有明确设计为本次交接的 upload ticket 可交给 Work 作为工具参数；它不证明生成来源，不写普通日志／Git，不在工具回执中回显。服务长期凭据和 read ticket 不进入 Work Prompt 或工具参数。本地探针的 bearer 功能不代表 ChatGPT OAuth／隧道已接通。未来外部连接必须明确真实身份认证和授权映射；配置与 CLI 登记结果保存在显式私有 `*.local.json`，不把密钥放命令行。日志只记录关联 ID、状态、长度和错误代码，不记录临时 URL 或认证头。

本地 REST 控制面为 `POST /control/attempts`、`POST /control/attempts/{requestId}/{attemptId}/cancel`；只读接口为 `GET /results/{requestId}/{attemptId}`、`GET /results/{requestId}/{attemptId}/blob/{version}`。控制／读取认证必须独立于 `/mcp` 写入角色，read 接口还校验该尝试的 read ticket；MCP writer 访问这些端点一律拒绝。可共用严格 loopback listener，但未来外部转发只能暴露 MCP 路径，不能把控制面一并导出。对象读取仅返回完整 Ready 的固定版本，不跟随客户端路径。前台 `monitorOnce({baseUrl,requestId,attemptId,readTicket,inboxRoot})` 有总超时、取消和有限轮询间隔，复核身份及完整字节 hash 后原子发布自己的 inbox 文件和 receipt；重复读取复用同一结果，已存在文件被改则拒绝。

### 来源、网络与完整发布

1. **来源不是模型声明。** `file_id`、文件名、模型提供的 conversation/result 字符串都不是独立来源证明。登记的 `expectedFileId` 必须来自关联当前 Work 生成结果的可信控制路径；在真实能力尚未证实时，允许完整字节进入隔离区并返回 `received_unverified`（语义 SourceUnverified），但不产生 Ready 清单或自动导入候选。错源直接拒绝。输入参考图 file ID／已知哈希和其他请求已占用源身份应拒绝；不能仅凭没有命中这些拒绝项认定是生成结果。本轮最小范围只在初次控制登记时绑定来源，未绑定对象继续隔离；后续若需补绑定，必须独立设计认证控制操作，不能由 uploader 调用或自报字段自动提升。
2. **受限文件获取。** 只接受 HTTPS、无 userinfo／fragment、明确允许的端口，以及配置中经实际官方 fileParams 来源核验的精确 origin；默认允许列表为空，未知域名失败关闭，不能猜测一个宽泛 OpenAI/CDN 通配域名。解析并校验所有 A/AAAA 地址，拒绝 loopback、私网、链路本地、保留／特殊地址及 IP 混淆表示；连接固定到已验证地址，同时保留原主机名做正常 TLS 校验，防 DNS rebinding。禁止自动重定向、代理继承和向源站转发 MCP／控制凭据。链接失效需平台提供新文件参数，不能爬取 ChatGPT 页面、调用未公开接口或改用任意 URL。测试里的假源注入只存在测试构造器，运行配置无“关闭校验”开关。
3. **真实字节和限额。** 成功状态且完整 EOF 后才记录完成；请求 identity encoding，拒绝意外压缩、截断和超限，流式计数至最多 40 MiB，长度头存在时必须一致，读取总时限 2 分钟。根据字节检测 PNG/JPEG，计算 SHA-256。服务端先检查尺寸／64 百万像素上限，再使用隔离模块的 sharp 完成受限解码，必须实际消费解码管线、拒绝损坏／截断，不能只读取 metadata。解码并发及像素输出内存有明确上限；原始存储字节不因解码而重编码改变。客户端仍独立核对长度／hash，产品接收模块继续原严格图片校验后才发布 Candidate。
4. **发布是不可变的。** 存储路径由服务器生成的对象 ID 派生，不使用入参文件名；固定私有根，拒绝路径穿越、reparse/symlink 与非普通文件，隔离数据不作为程序输入。临时文件写完并 flush，最终字节不可覆盖；最后原子发布含对象 ID、不可变版本、源 ID、长度和哈希的完成 manifest。崩溃在 manifest 前只留不可导入孤立文件；manifest 后重启可按已知身份恢复。版本是服务器生成的发布身份，不是假装是上游文件版本。监控每次按该版本读同一普通文件并重算 hash，异常不导入。
5. **幂等和停止。** 同一 request/attempt 的并行调用只产生一个发布结果；相同 source ID 和相同内容返回原回执，不建立新版本。相同身份却内容不同、第二个 source ID、旧尝试、失效 ticket 均返回冲突／拒绝，不覆盖已有对象。读取过程中和发布前重新检查撤销与登记版本；取消和最终发布串行裁决。停止后收到的完整文件最多隔离保留，客户端仍以本地当前 attempt/stateVersion 重新验证，不能因服务端先前已经发布而绕过停止。重启只查询已登记对象，不重发生图或上传。

### 本地证据与真实 Work 门槛

最小测试边界为：SDK initialize／tools/list／tools/call 与准确四字段文件 schema；REST 与 MCP 认证角色隔离／错请求／错源／旧尝试；未绑定源始终 SourceUnverified；40 MiB／像素边界、截断、损坏图片、哈希／类型不符；origin／私网／DNS rebinding／redirect 拒绝且无凭据泄露；同一尝试并行重复和内容冲突；第二存储拥有者拒绝、活锁不回收与已退出拥有者恢复；停止发生于读取／发布前后；manifest 发布前后崩溃恢复；监控只读指定对象和不可变版本，重启／重放不重复交付。采用最少有意义的真实文件／故障窗口用例，不用穷举生成大量镜像测试。

本地探针可用测试专用文件提供器，把明确的合成 PNG 经真实 MCP 调用、完整发布、有限时长轮询和独立 hash 读取跑通；报告为 `LOCAL_PROTOCOL_AND_STORE_PASS`，不能称为真实 Work 上传。前台 monitor 超时／取消会退出，不注册常驻任务；其读取通过不等于 ProcessingSession 已导入。新增模块的本地代码、测试与独立审查完成后仍不把 T02／T08／T11 或 Epic 标 Done。

`realWorkFileTransfer=NOT_RUN` 保持到：已授权可达连接完成发现和认证；对保留的实际 Work 输出调用 `save_image_result`，取得真实平台文件参数；独立控制路径证明源文件与该次生成绑定；完成字节发布；程序按对象／版本读取并独立校验。两条原链路都要提供这组证据，不能用合成输入、链接分享、文件名或模型“已上传”的回复代替。来源无法独立绑定时保留 SourceUnverified 和手动路线，自动通道禁用。不会重新启用浏览器控制下载作为备用方案。

路由记录：development-routing v2.4，继承 offset 0；本节架构工作 normal/requested/actual 为 `gpt-6-astra/high`，当前子代理 rollout 已有实际运行证据。架构决策完成后，本地网络／持久化／并发实现应切换或交接实际可验证的 Sol High 上下文；普通文档整理不使 Astra 常驻。新调用上下文的实际模型必须独立验证，本节不替其声明成功切换。

## 1. 用户目标与已确认约束

操作者希望在 PrintFlow 内填写设计需求，自动得到常用生图 Prompt，尝试调用网页端 ChatGPT Work 生图，再让程序取得图片作为设计素材。Prompt 可能依赖需要上传的参考图片或需求文件，不能被建模为纯文本输入。自动生图失败时仍能获得可复制的完整 Prompt，以及完成该 Prompt 所需的附件说明。

用户已确认：

- 使用已有个人 Plus／Pro 账号，不增加订阅。
- 优先使用免费方案；目前只有一台已有 Linux 服务器，可作为备用。
- 第一版采用已登录网页、本地接收和自动导入；Linux／MCP 中转留作可选扩展。
- 第一版输入包括 Prompt 与可选附件；有附件时必须先完成上传，再提交生图。
- 新功能与既有开发工作隔离。

此处的“免费”指不新增订阅、收费 API 或托管服务；生图仍受现有 ChatGPT 账号的额度和功能可用性限制。

## 2. 范围与验收结果

第一版交付一条单图片流程：

`设计需求＋附件 → 本地模板 Prompt → 附件上传确认 → 网页生图尝试 → 接收一张图片 → 校验 → 准备设计素材`

包括：

1. 首页进入独立的“AI 设计素材”页面。
2. 本地参数化的常用模板，可预览、编辑和复制 Prompt；可以选择多份参考图片或需求文件，为每个附件说明用途。
3. 浏览器桥接具备可用条件时，一次按钮操作先上传全部必要附件、确认网页接收，再提交一个 Work 生图任务。
4. 按请求编号接收一张原始图片，自动导入现有素材准备流程。
5. 页面保留明确的阶段、停止操作和失败原因；任何自动化失败都保留 Prompt 与附件清单，指出手动完成任务时需要上传哪些文件。
6. 用户手动完成生图后，可选择图片完成同一请求的素材导入。
7. 关联请求和导入会话，防止重复通知、重复点击和重启造成重复导入。

第一版不实现 Linux 服务部署、Google Drive／GCS 连接、MCP 上传服务、收费生图 API、批量生图、自动排版或直接生成生产 TIFF。它们不是本规格的验收条件。输入附件上传到 Work 属于本次范围；输出图片上传到 Linux／Google／MCP 属于后续扩展。当前分支不合并、不发布，也不更改生产安装或签署的工作站基线。

## 3. 方案选择与能力边界

选择本地 Chromium 浏览器扩展与 .NET Native Messaging 宿主配合。扩展负责网页；宿主负责本机文件交接；PrintFlow 负责需求、请求记录、校验和导入。

默认试用浏览器为 Windows 上的 Google Chrome。用户于 2026-10-05 明确指示“改用Chrome”，替代修订 0.2 的 Edge 验收配置；第一版自动化验收只要求一个经过实际验证的 Chrome 配置。真实 Work 模式、必要附件全部接收、单次提交、结果关联和唯一浏览器下载 ID 的要求保持不变。首次配置需要用户在该浏览器中登录 ChatGPT、加载本地扩展并登记其扩展 ID。缺少配置时 Prompt 功能照常可用，自动生图按钮说明缺少的条件。

这是一条需要真实网页验证的集成路线，不是已验证的成功承诺。浏览器扩展可以与本机宿主通信，不等于已经证明它可以完成 Work 生图。实现阶段必须验证 Work 入口、附件上传、提交、生成结果和下载的完整链路。无法证明的操作不得标记为已支持。

未选择的路线：

- Linux／MCP 中转：适合以后增加云端文件交接，但需要可访问服务、认证和传图能力；第一版不为它增加部署依赖。
- 仅 Prompt：是内置降级路线，不满足自动生图的完整目标。
- Workspace Agent API：官方提供异步触发和状态查询，但需要工作区授权，不能据此推定当前个人账号拥有该能力；API 当前也不直接提供 Agent 的最终回复。
- 付费 Image API：不符合“不增加费用”的当前约束，不作为失败后的自动替代。

不调用 ChatGPT 未公开的后台接口，不复制登录 cookie，也不把 Codex 当前聊天中的工具当作 PrintFlow 可以直接调用的产品 API。

## 4. 操作者界面

“AI 设计素材”是导入前的独立入口，不新增生产工作流类型。页面依次展示设计需求、Prompt 和当前请求结果。

初始模板固定为三个可编辑的印花场景：

- **单主体素材**：主体、风格、颜色、背景要求、构图和期望比例。
- **徽章图案**：主体、形状、风格、色数、文字和期望比例。
- **文字印花**：必须保留的文字、字体风格、装饰元素、颜色和期望比例。

主体或文字等必要字段为空时说明具体缺失项，不生成无内容 Prompt。每个模板给出默认构图、清晰边缘、完整主体和避免水印等要求；用户可以修改最终文本。输入按原文保留，不依赖另一个语言模型进行翻译或改写。

所有模板都允许引用参考图片和需求文件。页面展示附件的原文件名、上传名、类型、大小、用途与状态，允许提交前增加、删除和调整说明；含附件的请求仍只生成一张结果图片。

生成用 Prompt 与交接指令分开存储。交接指令要求生成一张图片并提供可下载结果；请求编号属于任务元数据，不作为要画在图片上的内容。引用附件的文字使用实际上传名和用途，例如“以 attachment-01.png 为主体参考；按 attachment-02.pdf 的配色要求绘制”，不能只在文字中给出 Windows 路径。

操作包括“选择附件”“生成 Prompt”“复制 Prompt”“自动生图”“停止”“选择已生成的图片”和“返回首页”。有请求运行时禁用第二次提交及附件修改；页面保留运行开始时的 Prompt 与附件快照，编辑表单不改变已提交任务。“停止”在 Queued 至 Validating 阶段可用，包含 Uploading；Importing 阶段显示“正在导入”，暂时禁用停止，直到现有导入事务给出确定结果。

下载并导入成功后进入现有 Workflow Selection，预选“准备设计素材”，由操作者继续。导入不是设计审阅、背景透明确认或生产文件批准。实际尺寸和透明通道来自文件检测，不能由 Prompt 的要求推定。

Prompt、附件用途、上传状态、错误和设置提示均提供现有中英文资源，与项目当前本地化方式一致。

### 4.1 附件输入与快照

第一版文件允许列表为 PNG、JPEG、WebP、PDF、TXT、Markdown、CSV、DOCX、XLSX 和 PPTX。图片单文件上限 20 MiB，文档单文件上限 40 MiB，一个请求最多 8 个附件且合计最多 80 MiB。这些是本产品的初始限制，不是对 ChatGPT 账号限额的保证；网页限制更严格或拒绝某格式时明确降级。程序不打开执行附件，也不在本机解析 Office 文件中的宏。

用户选择的文件复制为本功能拥有的不可变快照，原文件保持不变。附件清单包含附件 ID、顺序、原文件名、稳定上传名、用途、类型、大小、SHA-256 和受管快照引用。上传名按顺序生成，例如 `attachment-01.png`，避免同名文件混淆。附件不因其文件类型自动成为生成结果或设计输入；生成结果仍按第 8 节单独校验。

Prompt 的附件引用与清单中的稳定附件 ID 绑定，显示和提交时映射为可读上传名。删除被引用的附件后必须修正该引用才能提交；不从任意自然语言猜测电脑中的文件，也不自动收集整个目录。每份被选择并保留在请求中的附件都视为必要输入。

### 4.2 网页上传合同

Native Messaging 宿主只能读取本次请求清单中、哈希匹配的附件快照。附件字节通过有请求编号、尝试编号、附件 ID、顺序和长度的分块消息交给扩展；每块原始字节最多 256 KiB。扩展重组后核对完整长度与 SHA-256，再通过经过验证的网页文件上传控件提供真实文件内容。

使用页面标准的文件上传流程，不把本地路径当作已上传文件，不将完整附件编码塞进 Prompt，也不调用未公开上传接口。网页不接受程序提供的文件、上传需要不可自动处理的交互、格式不受支持或无法识别上传完成时，返回结构化失败并保留手动上传路线。

各附件记录 `Pending → Uploading → Uploaded`，失败记录为 `Failed`，取消记录为 `Cancelled`。只有网页对本次对话的所有必要附件给出明确的接收完成状态，且该状态与附件清单匹配，才能提交生图。部分上传成功不构成任务提交条件，也不允许静默丢弃失败附件继续生图。

### 4.3 降级时的完整交接

没有附件时仍提供普通可复制 Prompt。有附件时，复制内容包括生成指令、上传文件名及用途说明；页面保留对应本地快照的选择／打开入口，供用户手动上传。网页上传失败不会把 `Uploaded` 写入回执。界面明确区分“已提供上传指令”和“文件已上传”，不能只复制引用附件的文字便宣称输入已完整交付。

## 5. 模块与接口职责

| 模块 | 职责 | 对外合同与依赖 |
| --- | --- | --- |
| Prompt 模板模块 | 校验输入与附件引用、组合可编辑文本 | 输入模板 ID、字段和附件元数据，返回文本或字段错误；纯逻辑，无网络和文件依赖 |
| 附件快照模块 | 保存用户选择的文件、固定上传身份 | 输入用户选中的文件和用途，返回清单及受管快照引用；不上传原始路径或扫描目录 |
| 生图请求协调器 | 创建请求、保存上传及生图阶段、处理停止与恢复 | 调用请求存储、附件模块、生图通道、接收模块和导入入口；不识别网页控件 |
| Work 浏览器通道 | 上传附件、操作专用 Work 页面、报告阶段、取得下载身份 | 接收请求编号、Prompt、附件快照清单和一次尝试编号；返回逐附件回执及结构化状态或失败 |
| Native Messaging 宿主 | 本机附件字节、请求文件和结果图片的交接 | 仅接受登记的扩展来源，只读取拥有的快照；标准输入输出承载有长度前缀的 JSON，不混入日志 |
| 图片接收模块 | 校验下载身份、复制、检测并发布本地候选 | 返回应用拥有的候选引用、文件事实和哈希；不创建生产 Revision |
| 幂等导入入口 | 把候选交给现有素材导入流程 | 按请求编号最多关联一个 ProcessingSession；已有手动导入入口保持可用 |
| WPF 页面 | 展示需求、Prompt、进度和结果 | 仅依赖协调器视图合同，不直接操作浏览器、SQL 或任意文件路径 |

请求编号只是新功能请求的标识，不引入订单、客户或通用 Job 管理模型。自动生图通道与图片接收职责分开，后续 Linux／MCP 接收可以接在相同边界上，但本次不提供空壳服务器或假上传实现。

预期代码落点为现有 Domain／Workflow／Infrastructure／App 分层中的独立 AI 设计目录，另设浏览器扩展目录和小型 .NET 浏览器宿主项目。禁止把网页识别或接收逻辑塞进现有 Meitu／Photoshop 驱动。

## 6. 请求状态与持久化

状态采用有限、可测试的枚举：

`PromptReady → Queued → Uploading → Submitted → Generating → Receiving → Validating → Importing → Imported`

无附件的请求跳过 Uploading。含附件的请求必须满足全部 Uploaded 的前置条件才能进入 Submitted。

其他结束状态：`PromptOnly`、`Cancelled`、`Interrupted`、`ImportFailed`。

- `PromptOnly`：通道未配置、未登录、附件无法上传、功能或额度不可用、网页未识别、生成超时、结果不可下载或图片校验失败。保留 Prompt、附件清单、最后成功阶段和原因。
- `Cancelled`：操作者停止；本次尝试禁止继续提交、接收或自动导入。操作者之后明确选择重试或手动图片时建立新的尝试编号。
- `Interrupted`：进程或桥接意外结束，无法证明请求的实际进度；重启后不自动重新生图。
- `ImportFailed`：已收到有效图片，但现有导入流程失败；保留本地候选和关联的会话身份，不重新生图。

每个请求持久化模板版本、字段、最终 Prompt 快照、附件清单和逐附件上传回执、状态版本、尝试编号、时间、拥有的标签页／对话身份、下载 ID、候选引用、哈希、导入会话 ID 和结构化失败。不得持久化账号密码或 cookie。新的尝试复用已核验的本地快照，但不复用上一对话的上传成功回执。

记录保存在当前配置的 Workspace Root 下的 `AiDesign/Requests/<requestId>/`。通过进程间独占更新与临时文件原子替换，保证 PrintFlow 和宿主不会各自覆盖对方状态。状态版本、尝试编号和随机交接令牌必须同时匹配才接受回报。

一台安装同时最多一个自动生图请求。准备 Prompt 不需要取得 Meitu／Photoshop 的工作站自动化锁；浏览器使用本功能自己的占用合同。

## 7. 网页操作与图片交接

1. PrintFlow 先保存 Prompt、附件快照和请求记录，再尝试取得浏览器通道。
2. 扩展为该请求创建专用 ChatGPT 标签页，确认已登录和 Work 模式。不能识别 Work 时返回失败，不静默改用普通 Chat。
3. 有附件时通过真实文件上传流程上传快照；逐一取得与清单匹配的上传回执，确认全部必要附件已被网页接收。
4. 识别当前可见的输入与提交控件；在本次对话附件齐全的条件下记录提交身份，最多提交一次。
5. 根据明确的生成中、错误和完成状态报告进度，不以固定等待时间或出现任意图片作为完成证据。
6. 完成时必须把新生成的单张图片绑定到本次对话和尝试；上传的参考图、头像、旧图片、缩略图和其他标签页的图片不符合结果合同。
7. 使用经过验证的网页下载操作或网页已暴露的下载链接。通过浏览器下载 API 记录唯一 download ID 和完成后的文件位置；无法把下载唯一关联到该结果时返回 `PromptOnly`。
8. 宿主只接收该请求已登记的下载，检查配置的浏览器下载根目录、路径归属、普通文件属性和完整读取，再复制到本请求的暂存目录。不扫描整个下载目录寻找“最新图片”。
9. 接收模块检测真实内容，完成后原子发布候选。文件扩展名由真实 PNG／JPEG 类型决定。
10. PrintFlow 以应用拥有的候选引用和检测出的哈希调用素材导入入口；成功后展示对应会话。

Native Messaging 使用浏览器官方协议；登记限于当前 Windows 用户和本功能的宿主名、扩展 ID。第一版提供本地配套构建及显式登记／撤销步骤，不安装常驻服务、自动启动项或计划任务，也不发布扩展商店条目。

扩展只请求操作 ChatGPT 页面和完成上述交接所需的权限。第三方网页不能指定宿主执行命令或任意文件读写。

## 8. 文件检测与重复导入

第一版接受真实 PNG 和 JPEG；其他格式明确拒绝并提供手动回收提示。下载文件必须完整、非空且可以通过现有文件检测能力读取；上限为 40 MiB、64 百万像素。模板的目标比例、透明背景或印花适用性不是结构检测通过的依据。

候选先写到请求拥有的暂存文件，再按实际格式发布为最终候选；使用不会覆盖已有文件的命名和创建方式。接收期间损坏、中断或停止产生的暂存文件不进入导入入口。

导入关联必须在与新 ProcessingSession 的初始创建相同的 SQLite 事务内保存，并对请求编号设置唯一约束。不能在普通 `ImportAsync` 成功返回之后才写一份独立回执，否则崩溃窗口会重复创建会话。

新的幂等导入入口复用现有导入内部流程，按请求编号查找已有会话：

- 会话已导入成功：返回该会话，不复制第二次、不建立新 Revision。
- 会话已建立但导入失败或中断：返回同一会话及其实际状态，进入已有诊断／恢复路径。
- 尚未建立关联：原子建立关联和会话，再运行正常源文件快照、检测、哈希和 Revision 事务。

导入入口携带候选的预期哈希，并核对实际源快照的哈希；候选在交接后被改变时不能报告导入成功。浏览器只写接收候选，不能直接创建 Session、Revision 或批准记录。老的手动导入不要求请求编号。

## 9. 失败、停止与重启

所有失败保留可复制的 Prompt 与必要附件清单；失败提示区分附件快照、上传、网页提交、生图、下载、校验和导入。只有最终 `Imported` 可以称为已进入素材流程，网页提交成功不是生图成功。

一次尝试的附件上传合计时限为 5 分钟，生成阶段时限为 10 分钟，下载时限为 2 分钟。第一版不自动再次提交生图。用户明确重试会创建新的尝试编号，沿用或编辑 Prompt 及附件；旧尝试的迟到上传或下载消息不能覆盖新尝试。

在允许停止的阶段接受“停止”时，使交接令牌失效，停止发送后续附件字节，并禁止新提交和本地自动导入；协调器串行处理停止与进入 Importing 的决定，确保二者不能同时被接受。它会尝试使用经过验证的网页停止控件，但只有得到网页确认才声明远端已停止；无法确认时说明远端任务可能仍继续。已经上传到网页的附件不能被宣称撤回；停止后的迟到上传回执和下载不被自动采用。

重启把未完成的自动化请求显示为中断，保留 Prompt、附件快照和已收到的候选，不自动重新上传或提交。操作者可选择手动上传附件、继续接收已知候选或选择手动生成的图片；幂等导入入口保证不会建立第二个会话。

## 10. 设置与现有项目边界

AI 设计页面默认允许使用 Prompt。自动通道只有在浏览器扩展、宿主版本、扩展来源、下载根目录和网页适配检查通过时才可启用；否则页面展示具体原因。

默认接收目录随当前 Workspace Root 派生，不把真实图片、请求数据或账号信息写入代码仓库。单元和集成测试采用临时目录、合成图片与网页夹具，不使用客户作品和生产 Baseline。

既有 MVP 的本地处理、诊断和安装边界继续适用于旧流程。此次新需求只扩展独立的生成素材功能；上传对象仅限用户在本次请求中明确选择的附件。页面提交前展示实际将上传的文件，不从历史会话、客户素材目录、生产证据或诊断包自动收集文件。

现有包策略禁止 Selenium／Playwright；本方案不引入这两个依赖。现有产品／安装边界测试广泛检查网络 API；第一版本地扩展与 stdio 交接不要求给 .NET 产品增加 HTTP 下载器。现有测试不能因为新功能失败而被删除或整体放宽。

## 11. 验证与交付判定

自动测试覆盖行为和重要故障窗口：

- 模板必填项、文字原样保留、Prompt 编辑后的提交快照。
- 有／无附件、混合类型、同名附件、附件引用删除、数量／大小限制和原文件不变。
- 分块重组、长度／哈希校验、快照变化、错请求附件和旧尝试上传回执。
- 全部附件上传完成才能提交；部分失败、上传超时或上传中停止不启动生图。
- 通道未配置、未登录、额度不可用、未知网页和超时均保留 Prompt。
- 单次提交、重复通知、旧尝试回报、停止与迟到下载。
- 不属于本次请求的下载和路径、空文件、伪装扩展名、损坏或超限图片。
- 候选发布之前中断、导入事务之前／之后中断、重复导入与重启回收。
- WPF 运行中操作限制、Prompt-only 使用和中英文资源。
- 浏览器适配夹具中的 Work 模式、文件上传及确认、生成进度、参考图与结果的区分和下载归属。

真实验证只针对用户已有账号和同意启用的试用浏览器配置：先使用一条无附件需求，再使用带一张合成参考图和一份简短需求文件的印花需求，完成附件自动上传确认、提交、生成一张图片、本地回收、校验和导入；随后验证上传失败与停止／通道断开时 Prompt 及必要附件说明保留。

如果真实 Work 操作、附件上传或下载链路不可实现，必须报告具体失败环节；不能仅凭模拟测试把自动生图标记为完成。纯文本生图、带附件生图、Prompt 与手动回收能力分别报告验证状态。

用户已于 2026-10-05 批准修订 0.2，并要求先拆分和同步 Jira Epic 与 Tasks。本分支目前处于规格和待办准备阶段；后续按 Superpowers 流程形成实施计划，计划审阅和执行方式选择完成后才写功能代码。

## 12. 来源与推断

- [ChatGPT Image generation](https://learn.chatgpt.com/docs/image-generation)：官方说明网页聊天的生图入口；网页能力和限额依赖账号与工作区设置。它不证明本扩展自动化已经可用。
- [ChatGPT Work with files](https://learn.chatgpt.com/docs/artifacts-viewer)：官方说明在网页端 Work 附加来源文件；它不证明通过扩展上传当前网页已经完成验证。
- [Workspace Agent trigger runs](https://developers.openai.com/workspace-agents/trigger-runs)：异步触发、状态查询与当前无法直接检索 Agent 回复的限制。
- [Workspace Agent access tokens](https://developers.openai.com/workspace-agents/authentication)：工作区管理员设置和专用 token 的前提。
- [Microsoft Edge Native Messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging)：扩展与本机 Win32 宿主的 stdio 通信、来源登记和当前用户注册方式。
- [Chromium Downloads API](https://developer.chrome.com/docs/extensions/reference/api/downloads)：下载身份、状态和本地文件信息的交接基础。
- 当前仓库：`ISessionService.ImportAsync`、`SessionService`、`IWorkspace`、`IFileInspector`、WPF 导航、本地化资源、中心包策略与安装边界测试。

“本地浏览器桥接可避免新增云托管费用”是本设计的工程选择；“可以可靠自动控制当前 Work 网页”仍需要实施阶段的真实证据。规格没有假设个人账号拥有 Workspace Agent API 权限，也没有假设 Linux 或 Google 服务已经配置完成。
