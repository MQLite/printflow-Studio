## Hang diagnosis and minimal change

The blame sequence ended with `ManualResultImportTests.Interrupted_recovery_offers_restart_manual_import_and_abandonment` incomplete. That test started `SessionService.ExecuteAsync` using `FakeAdapterScenario.HangUntilCancelled` and `CancellationToken.None`, then abandoned the task to simulate a crashed process. `FakeAdapterExecution` waits indefinitely for cancellation. `SessionService.ExecuteAsync` holds a static per-session `SessionCompletionGate` for the call's lifetime. Startup recovery updates the persisted attempt to `Interrupted`, but it cannot destroy an in-memory gate while the old task is still alive in this testhost. The test then attempted `HandOff` on its original service, indefinitely waiting for that gate.

The original full run's owned process chain was `dotnet test` PID 10788 → VSTest PID 25980 → `testhost.exe` PID 26584. Blame terminated that testhost at the 120-second inactivity bound. The after-edit run's owned chain was PID 25292 → PID 26668 → PID 25508; testhost CPU reached 395.81 seconds and was still increasing near the eight-minute overall limit. Ctrl+C was sent only to the latter owned exec session, and these three PIDs were confirmed absent afterward.

The existing `SimulatedProcessDeath.BeginRecoveredProcess(report)` fixture removes only gates for sessions durably marked interrupted during startup recovery, modeling what a real process exit does. The test now invokes that fixture after recovery and uses a newly created service for its existing `Load`, `HandOff`, and `SubmitManualResult` operations. All original assertions remain. This changes the test's crash simulation only; product gate behavior remains intact. An independent read-only review found no actionable issue in this narrow change.
