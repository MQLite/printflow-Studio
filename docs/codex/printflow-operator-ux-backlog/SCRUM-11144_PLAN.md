Post-native boundary: the specialist proved `NtSetInformationFile` root-relative no-replace publication in five focused tests on the actual C: NTFS volume and returned ownership. Re-evaluated normal route: service, SQLite, recovery, targeted test and reporting work remains `gpt-6-sol/high` (`CONTINUE`); the fresh Astra safety review remains separate. Integrated replacement revealed NTFS file-system tunneling: immediately after a successful rename while its staged handle remains held, volume+FileId proves the same object even if the final creation time changes; the final handle's creation time is recorded separately. A restart with only a final name and differing stage creation time remains ambiguous and fails closed. This bounded implementation detail will be included in independent review; the historical design is unchanged.

Coalesced RequestId correction: the adopted delivery/attempt model needs an immutable `DeliveryRequestAlias` binding table for invocation IDs that coalesce onto an existing delivery. Without it, request B could coalesce with A and later be reused for a different destination/source. The extra table adds no delivery state: it records B→A, B's raw folder/name, and an exact-intent fingerprint in the same transaction. Different raw spellings/case/approved drive aliases that resolve to the same physical directory and normalized leaf still coalesce; B's later reuse must match its own bound raw intent, while reconciliation follows A's original destination. This is a source-level implementation refinement to preserve the reviewed RequestId contract, with no change to historical design files.

## Acceptance map

1. Approved valid output → equal-hash file and recorded verified path/hash: exact authority (slice 1), publication and verification (slice 3), atomic evidence (slice 2), integrated test (slice 4).
2. Existing same-name file → no overwrite and a collision-safe alternative suggestion: native race/collision test (slice 3) and service result (slice 4).
3. Managed workspace, protected original or snapshot → plain refusal: handle/alias protected-root checks and native tests (slice 3).
4. Cancel, read-only, disconnected, copy/hash failure → no partial final, unchanged approved source and retry without processing: native/fault tests (slice 3), staged recovery/result tests (slice 4).
5. Waiting review, rejected, invalidated, recycled or obsolete output → refusal: exact authority predicates and focused aggregate tests (slice 1).
6. Duplicate delivery → no recopy or production: SQLite coalescing (slice 2), recovery and service tests (slice 4).
7. Delivered only after final-name verification: native final handle/hash check (slice 3), durable Delivered plus preference transaction (slice 2), integrated result test (slice 4).

Additional accepted design requirements: destination preference only on successful save, restart state rediscovery, original-destination reconciliation, explicit successor-first missing replacement, actual TIFF physical dimensions, progress identity and verified-selection lease are slices 1–4. These are compatible backend contracts for amended 11145; 11145 UI/coordinator is not implemented here.

Each slice uses focused failing tests where practical, then implementation and a green targeted run. Required Windows-native evidence is separate from routed/fake tests. No full historical suite or unsafe startup/crop smoke. Stop an affected capability rather than weaken verified-handle/no-replace safety if the platform primitive cannot be made correct.
