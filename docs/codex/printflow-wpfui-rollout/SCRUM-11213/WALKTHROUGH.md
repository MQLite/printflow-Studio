## 招募和场次

对象为能阅读或听懂简体中文界面的实际老年操作员，或电脑操作不熟练的实际操作员。年龄段建议记录为 60–69、70+；非老年但低熟练度者可记录为 60 岁以下。年龄下限是本次招募建议，待负责人确认；不收出生日期。能否独立选文件、找文件夹、保存文件等自述用于说明熟练度，不能只以年龄推断。

记录匿名参加者代码、年龄段、熟练度和对本产品的熟悉情况。主持人、开发者或代理演示不算目标用户。重复参与者的练习/复测场次单列，不能充作新参加者。无需收集姓名、联系方式、单位、客户文件名或任务完成耗时；每位参加者可随时停止。

建议的至少 3 人和 80% 无提示完成率在正式开始前由负责人确认，确认内容写入场次记录。旧 SCRUM-11197/11155 走查明确不统计百分比和时间 KPI；本次仅将 C05 父计划的理解度比例作为待确认提案，不回写或改变旧项规则。目前没有用户观察，不能比较改写前后的真实理解率。

## 主持方法

开场只说明“我们在检查提示是否容易理解，不是在考你。请按自己的想法操作，不明白可以说出来，也可以随时停止。”先征得参加者对匿名文字记录的同意；不默认录音、录像。

每次只读 SCENARIOS 的“读给参加者”列，不提前教按钮、路线、术语或正确答案。在操作前后统一问：“你觉得现在到了哪一步？接下来会做什么？做完后会得到什么？”保留原话，再按主持人观察标准判断。

用户主动求助、主持人解释文字或指向控件，都记录具体提示。无提示自行纠正可独立完成，但仍记录误操作。安全介入后不能记无提示完成。若先展示旧文案，只能在主要任务完成后作为单独的文本比较，不先教答案；参与者对旧文案的回忆不能算旧版操作证据。

## 记录与判断

每个参加者的每个场景每次尝试单列，保留候选 ID、夹具、场景起点、结果、求助、误操作、原话、当前步骤/下一步/结果的解释及关键状态误判。原话必须来自实际发言；未观察填 null/UNOBSERVED，不能填写猜测或预期。

| 字段 | 允许值与规则 |
|---|---|
| result | NOT RUN、BLOCKED、PASS、FAIL。没有实际观察的场景不得 PASS。 |
| independent | YES：无操作性提示完成；NO：提示后完成或未完成；UNOBSERVED：未执行/无法观察。 |
| comprehension | 当前步骤、下一步、结果分别记 CORRECT、INCORRECT、UNOBSERVED，并附判断依据。 |
| criticalMisjudgment | YES、NO、UNOBSERVED。仅说对按钮名不足以判 NO；须说明状态后果。 |
| attemptType | first、retest、exploratory。每次独立记录，不覆盖原始失败。 |

关键状态包括审核/保存/完成、有历史/文件现存、核实同次保存/重新保存/另存、停止请求/停止完成、准备同事副本/已交接、导回/已审核、取消输入/放弃任务，以及环境检查历史/当前资格。任一误判须记录并整改复测；不能由总体完成比例抵消。

若负责人确认比例门槛，建议口径为每位合格参加者对全部预定核心场景的首次正式尝试：分子为无提示且任务及三项理解均正确、无关键误判的场景数；分母为该参加者全部预定核心场景数。BLOCKED、NOT RUN 不从分母悄悄删除，且有任何必需场景未观察时结论为 INCOMPLETE，不生成达标结论。逐人报告，同时列原始计数；总体平均不能掩盖个人未达标。复测另外报告，不能用复测替换首次数据。这是待确认的计算提案，本轮不计算。
