## Delivered behavior

- The authoring module binds explicit photos and existing assets by stable SlotId/AssetId. Replacing photos changes bindings without regenerating surrounding text or changing document-part identities. Inserted references carry explicit roles through save/reopen and Quick/Detailed roundtrips. Typed “图3” remains ordinary text. Removed references or explicitly unbound photos retain historical asset metadata and files.
- Export walks only the actual final document. Bound references expand to role and canonical upload name; missing references remain explicit pending placeholders with issues. RequiredAttachments is deduplicated by AssetId, sorted by persistent upload order and carries all currently used roles. Local selection paths are never generated into the handoff. Explicit BindExistingImage supports one photo serving multiple roles.
- Current distinct active images obey 8 files / 80 MiB total and 20 MiB per image, including document replacement and recomposition that reactivate old bindings. Inactive selections are individually verified without occupying current quota; historical assets do not count. Attachment limits now have one Workflow contract shared by the existing infrastructure constants. The existing durable sequence keeps upload names monotonic across replacement, removal, failure and restart.
- DraftId is the attachment owner under `AiDesign/Requests/<id>/Attachments/`; authoring does not create `request.json`, and old request listing ignores these directories. A failed draft CAS/publication cannot update the saved binding or attach a stale selection to a newer revision.
- VerifiedAiAttachmentReader validates the canonical manifest, seal, owner, regular file, length and complete hash. It pins ancestors plus seal/snapshot handles until its read-only stream lease is disposed, denying mutation/rebinding while the consumer reads. It exposes no reopening path. Explicit source selections likewise retain their first checked native handles and ancestry through copying, closing the old same-size substitution window between two opens.
- Photo binding uses the new VerifyImagesAsync capability on IAiDesignAttachments to check PNG/JPEG/WebP signatures on verified managed streams. General documents retain their previous verification contract. Filename extensions alone cannot admit renamed PDF/BMP files as photos. A signature is admission to a draft, not proof of complete image decoding or production readiness.
- FileAiAuthoringAssetPreview consumes that same verified stream on a dedicated STA worker, checks the container signature, decodes with WIC and returns an actual 96 dpi PNG payload bounded to a 2048-pixel longest edge. Source dimensions/transparency are reported; sources above 64 million pixels, missing codecs, undecodable data or cancellation return failures. No snapshot is rewritten.

The shared verified reader also backs the existing attachment verification/upload path. NativeHostSession consumes the lease's Stream; its messaging protocol, v1 Request schema, registration and production gates are unchanged. Existing two-argument module construction remains valid for non-image clients; image clients supply IAiDesignAttachments. Implementations without verified-image capability fail that operation explicitly.
